
## 1. Remove ALL GPU–CPU synchronization inside buffers
- delete synchronize() inside:
  - fill()
  - copy(from:)
  - toArray()
  - temporary() allocations
- guarantee: 2×–6× global speedup  
- absolutely required BEFORE any other optimization

---

## 2. Preallocate all intermediate tensors once
- eliminate DeviceFloatBuffer.temporary() inside token loops  
- allocate:
  - H_raw_inter
  - H_raw_ipt
  - H_raw
  - mu, gamma
  - S, M, G, H_fast, etc  
- reuse per-step
- removes ~150k allocations per training sequence  
- 10–20% speedup + lower CPU pressure

---

## 3. Fuse elementwise kernels
Replace sequences like:
- softlog → inhib_sub → inhib_div  
- mul → mul → scalar-mul → add  
- Hebb → ee → α·ee → subtract → scale → add  

With **one kernel per chain**:

- drastically reduces dispatch count  
- reduces memory bandwidth  
- 2×–5× speedup for Oja + cortex_step

---

## 4. Optimize GEMM tile sizes
Current: 32×32 (suboptimal for Apple GPUs)  
Upgrade to:
- **32×64** for tall matrices  
- **64×32** for wide matrices  
- use float4 loads  
- maximize threadgroup occupancy

Expected +1.5× to +3× GEMM speed.

---

## 5. Persistent encoders and command buffers
- keep 2–3 inflight command buffers  
- never call commit() except after N dispatches  
- never create encoders inside tight loops  
- batch 30–100 kernels per encoder  
Huge improvement to CPU overhead.

---

## 6. Rewrite reductions to shared-memory kernels
Replace multi-stage SIMDised reduction with:
- one kernel per reduction  
- warp-synchronous (SIMD32) reduction  
- threadgroup shared memory for block reductions

Reduces reduction cost from O(log n) dispatches → O(1) dispatch.

---

## 7. Optimize embedding lookup/update
- eliminate CPU-side offset copy  
- fuse embedding_row update into a single kernel  
- use float4 vector loads  
- better locality inside vocab matrix

5–15% throughput gain for large vocab sizes.

---

## 8. Reduce device buffer count & pointer movement
- avoid large numbers of tiny buffers  
- replace many small ops with shared temporary slabs  
- reduce encoded argument setup cost

---

## 9. Kernel launch scheduling / token batching
- group tokens in micro-batches of 4–8  
- allows more GPU overlap  
- reduces synchronization boundaries  
- improves ALU utilization

---

## 10. Optional: fuse GEMM1 → GEMM2 when shapes fixed
- only works if shapes are fixed (k,n,r constant)  
- compute (H_t0 A) B in one pass  
- reduces global memory traffic by 2×

---

## 11. Optional: fuse recurrent H update
Move:
- add_unsafe(H_t0, token)  
- H_t0 ← H_t1  
into a single internal state kernel.

---

## 12. Optional: implement persistent kernel approach
- run cortex_step + Oja loops inside one massive kernel  
- GPU pulls work from command buffer ring  
- extremely fast but requires major rewrite

---

## 13. Optional: replace float32 with float16 or bf16
- Apple GPUs have strong fp16 throughput  
- half-precision is stable for BDH architecture  
- 1.5×–2× speedup

---

## 14. Optional: use launch bounds / maxTotalThreadsPerThreadgroup tuning
- ensure optimal SIMD occupancy  
- ensure no warp underutilization  
- match tile size to simdgroup=32

---

## 15. Optional: ahead-of-time pipeline caching
- keep all pipelines preloaded  
- avoid any runtime searches for functions  
- small improvement but good hygiene
